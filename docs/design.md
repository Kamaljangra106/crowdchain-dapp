## Problem Statement
Build a mini crowdfunding project on Ethereum using a Solidity smart contract and MetaMask as the wallet. It is a college assessment, so the priorities are: it works end to end, the code is readable, there are tests, and the author can explain every piece (contract, wallet connection, events, deployment).

## What Makes This Cool
Money moves with no middleman, and the rules are enforced by code. If the goal is hit by the deadline, the creator gets the ETH. If not, every backer can pull their own money back. Nobody, including the author, can change that after deployment. The demo hook: create a campaign with a 2-minute deadline, contribute from MetaMask, wait, then watch the withdraw or refund button appear.

## Recommended Approach
Approach A. It is the smallest thing that still demonstrates every core Web3 concept: payable functions, state, time-based rules, events, access control, safe ETH transfers, MetaMask connection, testnet deployment.

### Contract: `Crowdfund.sol`
State:
- `struct Campaign { address creator; string title; uint256 goal; uint256 deadline; uint256 raised; bool withdrawn; }`
- `Campaign[]` (or `mapping(uint256 => Campaign)` plus `campaignCount`)
- `mapping(uint256 => mapping(address => uint256)) contributions`

Functions:
- `createCampaign(string title, uint256 goalWei, uint256 durationSeconds) returns (uint256 id)`. Requires goal > 0 and duration > 0.
- `contribute(uint256 id) payable`. Requires campaign exists, now < deadline, msg.value > 0. Increases `raised` and `contributions[id][msg.sender]`.
- `withdraw(uint256 id)`. Only creator, only after deadline, only if raised >= goal, only once. Set `withdrawn = true` BEFORE sending ETH.
- `refund(uint256 id)`. Only after deadline and only if raised < goal. Read the caller's amount, set it to 0, THEN send (checks-effects-interactions).
- Views: `getCampaign(id)`, `campaignCount()`, `contributionOf(id, addr)`.

Events: `CampaignCreated`, `Contributed`, `Withdrawn`, `Refunded`.

Rules (so the code and the report agree):
- Over-funding is allowed. The creator gets everything raised.
- Withdrawals are allowed only after the deadline. There is exactly one rule for "when is it over".
- Refunds are "pull" (each backer claims their own). Never loop over backers sending ETH.
- Use OpenZeppelin `ReentrancyGuard` on `withdraw` and `refund` as a second layer.
- Send ETH with `call{value: x}("")` and check the returned success flag.
- No owner, no admin, no upgrade path. Simpler to explain and nothing to abuse.

### Tests (Hardhat, JS or TS)
Must cover:
1. Create a campaign: fields stored, event emitted.
2. Contribute: totals update; zero-value rejected; contribution after the deadline rejected.
3. Goal met: creator withdraws exactly `raised`; second withdraw reverts; non-creator reverts; withdraw before deadline reverts.
4. Goal missed: backer refunds exactly their amount; second refund reverts; refund before deadline reverts; refund on a successful campaign reverts.
5. Reentrancy: a malicious contract tries to re-enter `refund`; it must fail or only receive its own amount.
6. Multiple backers and multiple campaigns do not interfere.
Use Hardhat's time helpers (`time.increase`) to jump past deadlines.

### Frontend (React + Vite + ethers.js v6)
- "Connect MetaMask" button using `window.ethereum` and `BrowserProvider`.
- Detect the wrong network and offer a switch (`wallet_switchEthereumChain`). Chain IDs: Sepolia 11155111, local Hardhat 31337.
- Listen for `accountsChanged` and `chainChanged`. Reload state on change.
- Campaign list: title, goal in ETH, raised, progress bar, time left, status (Active / Funded / Failed).
- Create-campaign form: title, goal (ETH), duration (minutes, so the demo is short).
- Contribute box with an ETH amount.
- Contextual buttons: "Withdraw" (creator, funded, ended) and "Refund" (backer, failed, ended).
- Every transaction shows pending, confirmed or failed states, and surfaces revert reasons in plain words.
- No MetaMask installed: show an install message instead of crashing.
